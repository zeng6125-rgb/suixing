## 1. phone-runtime 交付的接口（ui-shell 只消费）

### 1.1 AgentEngine 运行态与中断
```kotlin
data class StreamStats(
    val tokensOut: Int,          // 已解码输出 token 估算
    val thinkingTokens: Int,     // 其中思考 token
    val elapsedMs: Long,
    val tokPerSec: Float,        // tokensOut / elapsed，UI 直接显示
)
sealed interface RunState {
    data object Idle : RunState
    data class Running(val stats: StreamStats) : RunState   // 流式期间持续 emit
    data class Done(val stats: StreamStats) : RunState
    data class Cancelled : RunState
    data class Failed(val message: String) : RunState
}
```
- `AgentEngine.runState: StateFlow<RunState>`（新增，与既有 `AgentEvent` 事件流**并存**：事件一个不改，RunState 只承载运行态与速度；UI 现有事件订阅不许弄坏）。
- `AgentEngine.cancel(): Boolean`：**点停即停**。必须 `okHttpCall.cancel()` 中断在途流，并置标志让工具循环在下一个边界退出；返回是否真的中断了一个在途 run。不允许「等当前工具跑完才停」。
- `AgentEngine.steer(text: String): Boolean`：**插话**。把一句话排进队列，在下一个 model 边界作为 user 消息注入同一 run（不重启 run）；无在途 run 时返回 false。
- 思考流式：思考 delta 继续走现有流式通道，UI 侧折叠展示（见 2.3）。

### 1.2 Settings 键（data/Settings.kt，phone-runtime 加，ui-shell 读）
只新增一个：
```kotlin
val autoFollow: Boolean = true          // 聊天：在底部时自动跟随新消息
```
思考/工具折叠**复用既有的键**，不新造：`expandReasoning`（默认 false = 折叠）、`expandTools`、`showReasoning`。
序列化是 kotlinx.serialization + `ignoreUnknownKeys = true`，带默认值加字段即向前兼容，不需要迁移代码。
其余既有键不动：`themeMode`、`paletteMode`、`fontScale`、`cornerScale`、`rootAvailable`、`rootCheckedAt`、`alwaysAllowedTools`。

### 1.3 状态持久化（用户抱怨点①）
- **root 探测**：`CapabilityHub` 启动时**只读缓存**（`Settings.rootAvailable/rootCheckedAt`）直接上屏；**不再每次打开自动 `su -c id`**。仅两种情况重探：缓存不存在（`rootCheckedAt == 0`）、用户点「检测 root」。探测结果写回 Settings。
- **审批记忆**：「总是允许」已落盘（`Settings.alwaysAllowedTools`，ApprovalGate 启动即读，别重建）；补「总是拒绝」半边：新增 `Settings.alwaysDeniedTools: List<String>`，ApprovalGate 在弹询问前先查它、命中直接拒；两表重启后都生效，设置页权限区可清空（`forgetAlways` 已有，照样子加 forgetDenied）。
- **回前台刷新**：`SuixingApplication` 或 `MainActivity.onResume` 触发 `CapabilityHub.refresh()`（只读轻量状态：无障碍连接、Shizuku binder/授权），不触发 root 重探。

### 1.4 屏幕操作（对齐 Operit 的第一优先能力）
- 真屏注入走既有 `SuixingAccessibilityService` + `tools/UiTools.kt`：补齐 tap / long-press / swipe / type / open-app / back / home / recents / screenshot / 读节点树，缺哪个补哪个。
- **虚拟屏（Shower 式）本轮不做**，在 README 记为 v0.9 里程碑；本轮把真屏注入做稳。
- 新增**悬浮窗控制台**：`service/FloatConsoleService.kt`（前台服务 + `SYSTEM_ALERT_WINDOW`），overlay 上显示 RunState 摘要、停止按钮、插话输入框；全部通过 1.1 的接口驱动，不直接碰 UI 域代码。Manifest 的 service/permission 声明由 phone-runtime 加。

## 2. ui-shell 交付的界面（用户抱怨点②③④⑤）

### 2.1 导航改左侧栏
- 主结构 = `ModalNavigationDrawer`（或自绘抽屉）：**左侧栏顶部是对话列表，底部是设置按钮**；右侧不再放标签栏。
- 设置点进去是一个设置页，集中：模型/提供方、MCP、权限（capability）、外观、记忆、关于。现有散落的入口收编进来。

### 2.2 对话框改悬浮式（Gemini 风格，见用户截图）
- 悬浮胶囊：圆角容器浮在内容上方（带 elevation 与外边距），不贴底通栏。
- 行内布局：`[+ 附件] [文本框] [语音] [发送]`，**发送按钮与文本框垂直居中对齐**（当前版没对齐，必修）。
- `+` 号弹出：添加图片 / 文件（走既有附件能力）。
- 聊天区右下角**追底按钮**：不在底部时出现，点击滚到最新。
- 底部导航条（系统 nav bar）区域要适配 insets，悬浮胶囊不被遮挡。

### 2.3 消息与流式
- 一轮回复 = **一个气泡**，不再出现「思考卡 + 工具卡 + 正文」看起来像三块的分块感：思考与工具收进气泡内部的折叠区。
- 思考过程按 `Settings.expandReasoning` 默认折叠/展开（默认折叠），但流式期间始终实时显示 delta（用户要「显示思考流式」），结束后按设置收成折叠态。
- 气泡 meta 行显示：入/出 token、思考 token、缓存、耗时、**tok/s**（取 `RunState.Running.stats.tokPerSec`，Done 后定格）。
- **自动跟随**：列表在底部时新消息自动滚到底（`Settings.autoFollow` 可关）；用户上滑即脱离跟随，追底按钮出现。

### 2.4 图标
- 重画 `ic_launcher_foreground`：**白色线条/白色主体**设计（用户明确要白色），背景沿用自适应图标底色；foreground 与 monochrome 同步更新。

### 2.5 停止与插话的 UI 挂钩
- 运行中：发送按钮位变「停止」，点击调 `AgentEngine.cancel()`；旁边出现插话入口（小输入行），提交调 `AgentEngine.steer()`。
- 停止后界面立即回到可输入态（订阅 `RunState.Cancelled`），不等流自然结束。
