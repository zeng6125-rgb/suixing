# docs/ 索引

> **这个目录放什么**：跨版本、跨轮次仍需要被查的**设计与契约类文档**。
> **不放什么**：临时分析、发布记录、构建日志（那些在 `dist/`，本地产物，不入库）、代码本身的说明（写在代码注释里）。
>
> **维护规则**：
> 1. 本索引只描述**现状**，**不删除任何文档**；过期文档在下面的表里标注「已过期（见 TODO_NEXT.md）」，由 Lead/用户决定归档或删除。
> 2. 文档正文由它的原维护方维护；**本索引由仓库卫生轮次维护**（每次新增/重命名 `docs/` 下的文件都要在这里补一行）。
> 3. 文档里带 `文件:行号` 的引用**会随代码漂移**——用之前先按符号名 grep 复核（这条与 `WORK_MEMORY_suixing-agent.md` 的口径一致）。

## 加新文档的规矩

1. **先问是不是文档该进仓库**：一次性的分析结论、临时测量数据 → 写进 `WORK_MEMORY_suixing-agent.md` 的对应小节，或留在 `dist/`（本地产物）。只有**会被后来人反复查**的内容才进 `docs/`。
2. **进 `docs/` 的文件必须在本索引有一行**，且写清「是什么 / 什么时候读 / 谁维护 / 状态」。
3. **不再适用了就标注，不删除**：把状态改成「已过期（见 TODO_NEXT.md）」并指出替代物，删除与否由 Lead/用户决定。
4. 文档里引用代码位置用 `文件:行号` + 符号名，方便行号漂移后自己复核。
